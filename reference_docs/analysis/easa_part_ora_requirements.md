## 1. ATO 批准申请与批准证书（Approval Certificate）

### 1.1 申请材料（ORA.ATO.105 Application）
申请人（首次申请或变更申请）须向主管当局提交：
- 培训机构名称、地址
- 拟开始运营日期
- 培训负责人（Head of Training, HT）、飞行教员、模拟机教员、理论教员的个人信息与资质证明
- 拟使用的机场/训练场地 名称与地址（一个或多个）
- 拟用于训练的航空器清单：机型/级别/组别、注册号、所有人、适航证类别
- 拟使用的 FSTD（模拟机）清单
- 拟提供的培训课程类型及对应训练大纲（training programme）
- 运行手册（Operations Manual）与训练手册（Training Manual）
- 飞行试验培训机构（Flight Test Training Organisation）适用特例：仅需提交主基地机场/场地信息 + 试飞用航空器类型/类别清单

变更申请（ORA.ATO.105(c)）：仅需提交与变更相关的部分信息/文件。

### 1.2 批准证书内容（EASA Form 143 模板字段）
| 字段 | 说明 |
|---|---|
| 证书编号/参考号 | Certificate Number/Reference |
| 颁发主管当局 | Competent Authority 名称 |
| 培训机构名称、地址 | Name / Address of the Training Organisation |
| 依据法规 | Regulation (EU) No 1178/2011（+ Part-BFCL/Part-SFCL 如适用） |
| 批准范围声明 | "Part-ORA certified training organisation with the privilege to provide Part-FCL training courses, including the use of FSTDs, as listed in the attached training course approval" |
| 附件：培训课程批准（Training Course Approval，证书附件） | 逐条列出：培训课程名称/类型 + 对应可使用的 FSTD（含字母代码，对应FSTD资质证书上的代码） |
| 生效条件 | 仅在证书未被交回/替换/限制/暂停/吊销，且机构持续符合 Part-ORA、Part-FCL（及 BFCL/SFCL）等适用法规时有效 |
| 颁发日期、签字 | Date of issue / Signed by Competent Authority |

**关键设计要点**：
- **批准证书本身没有固定"到期日"**——不像执照/体检证有 expiry date，而是"持续有效直至被交回/替换/限制/暂停/吊销"（ORA.GEN.135 Continued validity）。软件里应建模为**状态机**而非"有效期倒计时"字段（虽然仍需支持监督/审核周期提醒）。
- 批准范围（scope）是**证书主体 + 附件"培训课程批准"列表**的组合，课程列表可独立变更（见第3节变更流程），因此数据模型上"证书"与"已批准课程列表"应为一对多关系，且课程列表可比证书本身更新得更频繁。
- 复杂 vs 非复杂机构判定（AMC1 ORA.GEN.200(b)）影响管理体系颗粒度要求（见第2节），软件应能存储/计算该判定结果：
  - 全职人力 > 20 FTE → 视为复杂机构；
  - 仅提供 LAPL/PPL/SPL/BPL 课程的 ATO、AeMC → 永远视为非复杂；
  - 提供 FFS 训练、多人制机型(MP)、零飞行时间训练(ZFTT)、复杂航空器、多个类别航空器、对应教员合格证课程、2个以上机场/场地的机构 → 永远视为复杂。

## 2. 管理体系要求（Management System, ORA.GEN.200/200A/210）

### 2.1 人员角色（数据字段：人员-角色-任命记录）
| 角色 | 法规依据 | 职责要点 | 记录要求 |
|---|---|---|---|
| **负责人 Accountable Manager** | ORA.GEN.210(a) | 对机构财务与运行合规拥有最终权力；对安全负直接责任；负责建立并维护管理体系 | 任命记录、变更记录 |
| **合规负责人/人（组）Nominated Person(s) for compliance** | ORA.GEN.210(b) | 确保机构持续符合适用要求；最终对负责人负责 | 可为一人或一组人 |
| **安全经理 Safety Manager**（复杂机构，AMC1 200(a)(1)） | AMC | 协调安全管理体系(SMS)日常运作：危险源识别、风险缓解监督、安全绩效报告、SMS文档维护、安全培训、内部事故调查 | 可与合规监督经理为同一人（需负责人确保双重职责资源充足） |
| **合规监督经理 Compliance Monitoring Manager**（AMC1 200(a)(6)） | AMC | 建立/维护合规监督大纲(CMP)；独立于被审核职能；直接向负责人汇报；非复杂机构可由负责人本人兼任（需具备相应能力） | — |
| **培训负责人 Head of Training (HT)** | ORA.ATO.110 | 确保培训符合 Part-FCL/BFCL/SFCL；飞行/模拟机/理论训练的有机衔接；监督学员进度 | 需有丰富教员经验+管理能力 |
| **总飞行教员 Chief Flight Instructor (CFI)**（CPL/MPL/ATPL机构，ORA.ATO.210(b)） | 法规 | 监督全体飞行/模拟机教员；训练标准化 | 持最高级别执照+教员证 |
| **总理论教员 Chief Theoretical Knowledge Instructor (CTKI)**（ORA.ATO.210(c)） | 法规 | 监督理论教员；理论训练标准化 | — |
| **安全评审委员会 Safety Review Board**（复杂机构） | AMC | 负责人主持，各职能负责人组成，监督安全绩效、行动落实、体系有效性 | 会议记录 |

**注**：HT/CFI/CTKI 三职位在提供综合课程(integrated course)的ATO中不得由同一人兼任；其他情况下可合并由1-2人担任（需证明能力充分）。飞行教员师生比不超过 1:6（不含HT）；实操类地面课堂人数不超过28人。

### 2.2 SMS（安全管理体系）核心要素（ORA.GEN.200(a)）
组织须建立、实施、维护包含以下要素的管理体系：
1. 明确的职责与问责线，负责人对安全负直接责任
2. 安全政策（Safety Policy）
3. 危险源识别、风险评估与缓解（含变更管理 Management of Change、应急响应计划 ERP）
4. 人员培训与胜任力维护
5. 管理体系关键流程文档化 + 人员知悉责任的流程 + 文档修订流程
6. **合规监督功能（Compliance Monitoring）**：含向负责人反馈发现问题的机制，确保纠正措施有效落实
7. 其他法规（(EU)2018/1139、376/2014）附加要求

**特例（非复杂机构简化路径）**：仅提供 LAPL/PPL/SPL/BPL 课程的机构，风险管理与合规监督可通过**每日历年至少一次的机构自查（organisational review）**代替，结果须及时通报主管当局。（软件应支持"年度自查"任务类型 + 自查清单模板，见 GM2 ORA.GEN.200(c) 列出的典型检查项：批准范围合规、训练大纲/教材合规、训练设备/设施、人员资质、承包方管理、安全培训沟通、管理体系文档、记录保存抽查、应急响应、内部安全报告分析、风险登记。）

### 2.3 信息安全管理体系（ORA.GEN.200A，2026-02-22起适用）
组织须另外按 (EU) 2023/203 建立信息安全管理体系（ISMS），管理可能影响航空安全的信息安全风险。**软件设计提示**：需为2026年2月新规预留合规模块。

### 2.4 合规监督（Compliance Monitoring）
- 需制定合规监督大纲（CMP）：监控范围至少含：机构特权范围、手册/日志/记录、培训标准、管理体系流程与手册
- 审核/检查须由独立于被审核职能的人员执行（内部或外部均可，外部人员仍在合规监督经理责任下）
- 文档须包含：术语、活动标准、职责分配、合规程序、监督计划排期、审核程序、报告程序、跟踪与纠正措施程序、记录系统、培训大纲、文档控制
- **数据模型建议**：审核计划(Audit Schedule) → 审核任务(Audit/Inspection) → 发现项(Finding, 分级如ARA.GEN.350的Level 1/2) → 根本原因分析 → 纠正措施计划(Corrective Action Plan) → 验证关闭(Closure)，形成闭环状态机。

### 2.5 承包活动（Contracted Activities, ORA.GEN.205）
- 组织对外包/采购活动的合规性负最终责任
- 承包方若未持有相应资质，则在"委托方批准范围下"运行
- 需要书面协议明确承包范围与适用要求；承包方纳入委托方的安全管理与合规监督范围

### 2.6 记录保存总则（ORA.GEN.220）——见第7节汇总表

### 2.7 事件报告（ORA.GEN.160 Occurrence Reporting）
- 强制性报告：安全相关事件/事故须报告主管当局，最迟不超过发现后 **72小时**
- 需包含强制与自愿报告双通道
- **软件设计提示**：需要"事件报告"实体，字段含：报告时间、发现时间（用于计算72小时时限）、事件类型、涉及人员/航空器/FSTD、报告去向（主管当局/设计批准持有人/State of Registry）、跟进报告(follow-up report)状态。

## 3. 培训课程管理

### 3.1 课程/大纲批准与变更流程
- **训练大纲（Training Programme, ORA.ATO.125）**：每种课程类型须制定独立的训练大纲，须符合 Part-FCL/BFCL/SFCL（及试飞课程符合Part-21）要求
- 对CPL/MPL/ATPL类课程（ORA.ATO.225）：训练大纲须包含飞行与理论训练的周/阶段分解表、标准科目清单、大纲摘要；具体内容与顺序在训练手册(Training Manual)中规定
- **变更管理（ORA.GEN.130，详见第8节）**：课程/范围变更属于"需事先批准变更"类别

### 3.2 训练手册与运行手册（ORA.ATO.130/230）
- ATO须建立并维护训练手册（Training Manual）+ 运行手册（Operations Manual）
- 须向员工及（适当时）学员公开手册内容及ATO批准文件
- 试飞培训机构：运行手册须符合 Part-21 试飞运行手册要求
- 运行手册须为飞行教员建立飞行时间限制方案（最大飞行小时/值勤小时、最小休息时间，参照Part-ORO）
- 训练手册须写明各训练阶段的标准、目标、训练计划、简报与空中科目、FSTD训练（如适用）、理论训练

### 3.3 特殊课程类型（软件应作为课程子类型建模）
| 课程类型 | 关键规则 |
|---|---|
| 远程学习模块课程 (ORA.ATO.300) | 仅限LAPL/PPL/SPL/BPL理论课程、附加型别/级别理论课程、多发直升机首次型别前理论课程；课堂教学占比不得低于总课时的10% |
| 零飞行时间训练 ZFTT (ORA.ATO.330/335) | 仅限具备商业航空运输资质或与运营人有专项协议的ATO；运营人须有至少90天该机型运行经验（特定条件可豁免） |
| 多机组驾驶员执照 MPL (ORA.ATO.350) | 仅限具备商业航空运输资质或专项协议的ATO |
| 试飞培训 Flight Test Training (ORA.ATO.355) | 须满足Part-21要求 + 与雇佣试飞人员的Part-21机构有专项协议 |
| 第三国培训 (ORA.ATO.150，仅IR课程) | 须在成员国境内完成"适应性飞行"及IR技能考试 |

### 3.4 训练用航空器与场地（ORA.ATO.135/140/145）
- 须证明训练用航空器/FSTD符合适用要求，且与训练大纲相匹配
- 学员须满足Part-Medical、Part-FCL规定的训练前提条件（含体检证有效性，见第5节）

## 4. 人员记录管理（教员/考试员）

**说明**：教员（FI/TRI/SFI等）与考试员(Examiner)的**具体资质标准、复训/复验周期**主要规定在 **Part-FCL**（本次任务范围为Part-ORA，未展开精读Part-FCL），Part-ORA 仅规定 ATO 作为组织**必须持有并维护**相关记录、任命合规人员：

- ORA.GEN.210(c)(d)：机构须配备足够数量的合格人员；须**维护经验、资质、培训记录**以证明合规
- ORA.ATO.110(c)(d)：理论教员须有航空实践背景+教学技巧培训，或有理论教学经验+相应理论背景；飞行/模拟机教员须持有 Part-FCL/BFCL/SFCL 规定的相应资质
- ORA.ATO.210 + AMC：HT须持有(或3年内持有过)相关专业飞行执照；CFI须完成1000小时PIC飞行时间（其中至少500小时为相关教学任务，可含200小时仪表地面时间）
- 理论教员上岗前须通过试讲考核证明能力（AMC1 ORA.ATO.110(c)）

**软件设计建议**：人员实体需要字段：姓名、角色（HT/CFI/CTKI/FI/TRI/SFI/理论教员/考试员/合规监督经理/安全经理/负责人）、任职起止日期、持有执照/教员证/考试员证编号与有效期（关联到Part-FCL颁发的证照，非ORA本身管理）、经验小时数记录、上岗前评估记录（如试讲）、变更通知记录（见第8节，人员变更需在计划变更前至少10天通知主管当局）。

## 5. 学员记录管理

### 5.1 学员记录内容与保存期（ORA.ATO.120 Record-keeping）
课程期间及**结课后3年**须保存：
(a) 每名学员的地面、飞行、模拟飞行训练详情
(b) 教员详细且定期的进度报告（含评估、阶段性进度飞行测试与地面考试）
(c) 学员执照、相关签注/证书信息，**含体检证与签注的到期日期**

- 非商照课程（LAPL/PPL/SPL/BPL）可采用"学员进度卡"（progress card）形式，须覆盖全部训练大纲科目，教员完成/评估后须签字确认（AMC1 ORA.ATO.120(a)(b)）

### 5.2 体检证有效性核查
- 明确要求 ATO 记录学员**体检证及签注的到期日期**（ORA.ATO.120(c)），意味着系统需要：
  - 体检证到期日字段 + 到期提醒
  - 训练前置条件校验（ORA.ATO.145）：训练开始前系统应校验学员是否满足 Part-Medical、Part-FCL 规定的前提条件（含体检证有效）

### 5.3 缺勤/补训
- Part-ORA本身未对"缺勤/补训"给出专门条款，但通过以下机制间接约束：
  - 远程学习课程（ORA.ATO.300 AMC）：要求每周学习≥15小时的规划基准、每15小时安排一次进度测试、自评测试间隔5-10小时——软件可用于建模"学习进度跟踪"与"逾期提醒"
  - 模块课程有 Part-FCL 规定的**课程完成时限**（须查Part-FCL获取具体年限，Part-ORA仅要求ATO"维护全面记录以确保学员按时限完成模块课程"，AMC1 ORA.ATO.300(a)）

## 6. 模拟机/FSTD 组织责任

### 6.1 FSTD 使用资格证明（ORA.ATO.135）
ATO 仅当向主管当局证明以下事项后，方可用FSTD开展训练：
1. FSTD 规格与训练大纲的适配性
2. FSTD 符合 Part-FCL 相关要求
3. （FFS全动模拟机）FFS 能准确代表对应机型
4. 已建立监控FSTD变更的制度，确保变更不影响训练大纲的适配性

### 6.2 FSTD运营组织的管理体系义务（ORA.FSTD.100/105/110/115/120）
- 申请FSTD资质证书者须证明已按 ORA.GEN Section II 建立管理体系
- **维持资质（ORA.FSTD.105）**：须在**12个月周期**内逐步完成 MQTG（主鉴定测试指南）全套测试+功能/主观测试；结果须注明日期、标注已分析评估，并按 ORA.FSTD.240 保存
- 须建立**构型控制系统**确保FSTD软硬件持续完整性
- **变更/改装（ORA.FSTD.110）**：影响操纵特性、性能、系统运行的改装，或运动/视景系统重大改装，须评估对原鉴定标准的影响并重新测试；重大变更须提前告知主管当局
- **安装/场地（ORA.FSTD.115）**：FSTD须处于安全可靠环境；人员须接受FSTD安全简报；安全特性（如紧急停止、应急照明）须**至少每年检查一次并记录**
- **额外设备（ORA.FSTD.120）**：非鉴定要求的附加设备须经主管当局评估，确保不影响训练质量

### 6.3 FSTD资质持续有效与延长评估周期（ORA.FSTD.225）
- 资质证书持续有效条件：FSTD及运营组织持续合规；主管当局可访问检查；证书未被交回/吊销
- 若主管当局批准延长复检周期，组织须指定具备经验的人员（组），在每12个月周期开始前60天至开始后30天内完成：复检MQTG全套测试重跑、功能/主观测试、向主管当局提交报告
- 变更/迁移/停用须提前通知主管当局（ORA.FSTD.230）：
  - 升级鉴定等级需重新走全套验证测试（不得沿用历史评估结果）
  - 迁移场地：迁移前完成至少1/3验证测试+功能/主观测试，测试文档与FSTD记录一并保存备查
  - 长期停用：须与主管当局约定停用/存储/复活计划

**软件设计要点**：
- 记录保存期限**应作为可配置的"保留策略(retention policy)"字段挂在每类记录实体上**，默认值5年，个别类型（学员记录3年、FSTD终身记录）单独配置，避免硬编码。

- 电子记录需满足：24小时内自动备份、异地备份存储、防篡改（操作日志/审计轨迹）、在保留期内保持可读性（格式迁移时的数据完整性保障）。

## 8. 变更管理（机构/人员/课程变更向主管当局报告）

### 8.1 变更分类（ORA.GEN.130）
| 变更类型 | 处理方式 | 时限 |
|---|---|---|
| **需事先批准（Prior Approval）** | 变更前须申请并获得主管当局正式批准后方可实施；期间须按当局规定条件运行 | 建议至少提前 **30天** 提交申请（AMC1 ORA.GEN.130(a)） |
| **计划性人员变更（Nominated Person变更）**（需事先批准范畴的子类） | 提前通知 | 至少提前 **10天** 通知 |
| **无需事先批准（管理并通知）** | 按机构内部已获批准的"变更管理程序"执行，事后通知当局 | 应在有变化时尽快通知（意外变更应尽早通知） |

**典型"需事先批准"变更清单（GM1 ORA.GEN.130(a)）**：
1. 机构名称
2. 主要经营场所地址
3. 机构活动范围（scope of activities）
4. 机构新增地点
5. 负责人（Accountable Manager）变更
6. ORA.GEN.210(a)(b)所指人员变更（负责人、合规负责人等Nominated Persons）
7. 机构文档（含安全政策与程序）变更
8. 设施变更

**典型"无需事先批准"变更清单（GM1 ORA.GEN.130(c)）**：
- 医疗设备（如ECG、检眼镜）
- FSTD运营方技术人员
- 预防性维护排班变化
- 教员名单

**机构改名的特殊处理（GM2 ORA.GEN.130(a)）**：视为须紧急提交的新申请；若改名是唯一变更，可附上此前以旧名义提交的文档作为合规证明。

### 8.2 状态机建议（软件设计）
```
[草稿 Draft] 
   → [已提交变更申请 Submitted]（需事先批准类）
       → [当局审核中 Under Review]
           → [批准 Approved] → 生效，更新证书/附件
           → [驳回 Rejected] → 退回草稿
   → [已记录待通知 Logged]（无需事先批准类）
       → [已通知当局 Notified] → 生效
```
- 每条变更记录字段建议：变更类型（需批准/无需批准）、变更对象（证书本体/课程列表/人员/设施/地址/文档）、提交日期、生效日期、当局回复/批准文号、关联的旧值与新值（用于审计轨迹）。
- 负责人/合规负责人等 Nominated Person 变更需要"继任任命"流程，与人员记录模块联动（第4节）。

### 8.3 持续有效性（Continued Validity, ORA.GEN.135）
- 证书持续有效的三个条件：①机构持续合规（含发现项整改，ORA.GEN.150）；②配合当局访问检查（ORA.GEN.140）；③证书未被交回或吊销
- 发现问题处理流程（ORA.GEN.150 Findings）：①根本原因分析 → ②制定纠正措施计划 → ③在当局约定期限内完成整改并证明给当局看。此流程应与第2.4节合规监督的"发现-整改闭环"共用同一数据模型。
